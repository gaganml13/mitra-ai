Hackathon Build Plan

MILO.

The smart companion toy that grows with your child

15 days pre-work
24 hrs hackathon build
4 features finalized
Ages 3 – 8 yrs
Finalized features
01 / SAFETY
Cry Alert
Toy detects infant crying using an audio classifier running in a background thread. Instantly plays a pre-recorded parent comfort clip and fires a push notification to the parent's phone with timestamp and duration.
02 / ENGAGEMENT
Sentiment-Adaptive Storytelling
AI detects the child's mood via voice analysis (pitch, pace, volume). Responds with humor, storytelling, and age-appropriate energy matching the child's current state — never boring, never overwhelming.
03 / CONNECTION
Parent Voice Layer
Parents record 20 tagged phrases in the app — comfort, praise, bedtime, greeting. The toy plays these at emotionally matched moments, making the child feel the parent's presence even when they're away.
04 / LEARNING
Q&A and Interaction
Full voice-based conversation powered by Groq (Llama 3). Child asks anything — space, animals, "why is the sky blue?" — and Milo answers in a warm, child-safe, curiosity-first way under 500ms.
15-day build plan
Phase 1
Core Voice Loop
Days 1 – 4
Day 1
Environment setup
  • Buy hardware: laptop, USB mic, speaker, toy shell
  • Install Python 3.11, pip dependencies
  • Test mic input and speaker output with PyAudio
  • Create project repo and folder structure
Day 2
Speech-to-text
  • Integrate OpenAI Whisper (base model, local)
  • Record audio → transcribe → print text loop working
  • Add silence detection to stop recording naturally
  • Test accuracy with child-like speech samples
Day 3
LLM + TTS
  • Set up Groq API key, test Llama 3 response
  • Write child-safe system prompt with storyteller persona
  • Integrate pyttsx3 TTS for spoken output
  • Full loop: speak → hear → reply → speak working
Day 4
Stabilise loop
  • Add wake word detection (pvporcupine or keyword match)
  • Handle interruptions and silence gracefully
  • Modularise code: each feature is a plug-in file
  • Run 30-min continuous test, fix crashes
Day 4 output → A toy that wakes up, listens to a child, and has a real conversation. Feature 4 (Q&A) is complete.
Phase 2
Sentiment + Storytelling
Days 5 – 8
Day 5
Audio mood analysis
  • Install librosa, run on recorded audio clips
  • Extract: avg pitch, speech rate, volume variance
  • Map features to 4 mood buckets: sad, tired, excited, calm
  • Test with 10 different voice samples, tune thresholds
Day 6
LLM mood injection
  • Pass mood tag into Groq system prompt dynamically
  • Write persona rules: sad → gentle story, excited → playful
  • Add humor instructions: puns, funny voices, silly comparisons
  • Test: same question, different moods → different replies
Day 7
Storytelling mode
  • Build "story trigger" — if child says story/tell me — switch mode
  • LLM generates 3-part story with cliffhanger + resolution
  • Add TTS speed variation: slow for sad, fast for excited
  • Test full story flow start to finish with a real child if possible
Day 8
Polish + test
  • Run 20 real conversation tests, note where it feels robotic
  • Tune system prompt based on feedback
  • Ensure mood detection doesn't slow response under 700ms
  • Log mood + topic data to JSON file for parent app later
Day 8 output → Milo adapts tone, tells stories with humor, and responds to how the child is feeling. Feature 2 complete.
Phase 3
Cry Alert + Parent Voice
Days 9 – 13
Day 9
Cry detector
  • Download YAMNet TFLite model, run on sample audio
  • Run classifier in separate background thread (threading.Thread)
  • Set confidence threshold: cry detected if score > 0.6 for 3s
  • Print "CRY DETECTED" to console with timestamp
Day 10
Firebase + push alert
  • Create Firebase project, enable Realtime DB + FCM
  • On cry event: write to Firebase {time, duration, confidence}
  • Set up FCM push notification to parent phone
  • Test: simulate cry audio → phone notification fires in <5s
Day 11
Parent voice clips
  • Build clip recording script (or simple web form)
  • Define 5 clip categories: comfort, praise, greeting, bedtime, gentle-scold
  • Record a test set of 20 clips using a teammate's voice
  • Store as /clips/comfort_1.mp3 etc., build lookup table
Day 12–13
Clip trigger logic
  • LLM tags each response with emotion category
  • On cry: immediately play comfort clip, skip LLM call
  • On praise moment in Q&A: play praise clip after LLM response
  • On bedtime keyword: switch to bedtime mode, play lullaby clip
Day 13 output → Cry is detected + parent is alerted + comfort clip plays. Parent voice feels present. Features 1 and 3 complete.
Phase 4
Parent App + Final Integration
Days 14 – 15
Day 14
Parent app
  • React + Vite app: 3 screens — Dashboard, Voice Studio, Alerts
  • Dashboard: daily report card from JSON log (topics, mood arc)
  • Alerts screen: list of cry events with time and duration
  • Voice Studio: record + upload clips, tagged by category
Day 15
Integration + dry run
  • Full system test: all 4 features running simultaneously
  • Simulate complete hackathon demo start to finish
  • Fix any crashes, edge cases, latency spikes
  • Pack go-bag. Freeze the code. No new features after Day 15.
Day 15 prep
Demo rehearsal
  • Assign speaking roles to each teammate
  • Prepare live parent voice recording moment for judges
  • Have cry simulation audio file ready to trigger on command
  • Charge everything. Bring backup hotspot + power bank.
Day 15 output → Milo is fully integrated, demo-rehearsed, and ready to win. All 4 features live, parent app live, toy packaged.

Software · STT
OpenAI Whisper
Speech-to-text. Converts child's spoken words into text for the LLM. Runs locally (base model). Handles accents and child speech patterns well.
Free · Python
Software · TTS
pyttsx3 / gTTS
Text-to-speech for LLM responses. pyttsx3 is offline and instant. gTTS (Google) sounds more natural. Use pyttsx3 as fallback if internet drops.
Free · Python
Software · Audio
librosa
Mood detection engine. Extracts pitch, speech rate, and volume variance from audio. Maps to sad / tired / excited / calm. Runs in under 100ms per clip.
Free · Python
Software · Audio
YAMNet (TFLite)
Cry detection classifier. Pre-trained Google audio model that recognises crying, screaming, and distress sounds. Runs in a background thread continuously while toy is on.
Free · TensorFlow Lite
Software · Audio
PyAudio
Low-level audio capture from USB mic. Feeds raw PCM audio into Whisper, librosa, and YAMNet simultaneously using Python threads.
Free · Python
AI · LLM
Groq API (Llama 3)
Core intelligence. Powers all Q&A, storytelling, humor, and conversational responses. Sub-500ms latency. Free tier sufficient for hackathon. Receives mood tag in system prompt to adapt tone.
Free tier · API
AI · Prompt
Child-Safe System Prompt
The personality layer. Instructs LLM to be warm, funny, curious, age-appropriate, and story-driven. Includes mood signal injection and topic safety rules. The most important 200 words in the project.
Crafted manually
Backend
Python Flask
Lightweight local server connecting the toy's Python brain to the parent React app. Exposes REST endpoints: /log, /clips, /alerts. Runs on localhost during hackathon.
Free · Python
Backend · Cloud
Firebase (RTDB + FCM)
Two jobs: Realtime Database stores cry events and conversation logs in real-time for the parent app to read. FCM (Firebase Cloud Messaging) sends push notifications to the parent's phone on cry detection.
Free tier · Google
Frontend
React + Vite
Parent app. Three screens: Dashboard (daily report), Alerts (cry log), Voice Studio (record clips). Runs as a mobile web app — any judge can open it on their phone during the demo.

Mood arc chart in the parent dashboard. Shows the child's emotional state across the day as a simple line chart. Makes the sentiment analysis feature visible and tangible to judges.

Hackathon rules to follow
01
Freeze code at Day 15
No new features once you walk in. The 24hrs is for wiring, polishing, and recording the live parent voice session — not building new things.
02
Never show a terminal to judges
All demo interaction happens through the toy and the parent app on a phone. The laptop stays hidden. Judges should never know it's a laptop.
03
Record parent voice live
At the hackathon, do the parent recording in front of judges. Let them say a phrase into the phone, then watch the toy play it back to the "child." That 30 seconds wins the room.
04
Prepare cry simulation
Have a 5-second cry audio file you can play near the mic on command. Triggering the alert live during a demo is more powerful than explaining it.
05
One person owns each feature
No shared ownership. Cry alert = Person A. Voice layer = Person B. App = Person C. LLM + sentiment = Person D. Everyone knows their module cold.
06
Sleep in shifts at hr 18
Lock the build at hour 18. One person stays awake to monitor. Everyone else sleeps. A rested team presents 10× better than an exhausted one.
