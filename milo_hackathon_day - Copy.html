Hour-by-hour hackathon schedule
Hr 0 – 8
Integration
Phase 1
Set up, connect everything, first live system test
INTEGRATION SPRINT
Hr 0–1 · Unpack
Set up laptop, mic, speaker, toy shell at your table. Boot everything. Confirm internet via hotspot. Don't depend on venue WiFi.
Hr 1–3 · Wire modules
Connect all pre-built modules into one running process for the first time. Cry detector + mood engine + voice loop + clip player all running together.
Hr 3–5 · Record parent voice
Do this early. One teammate acts as the "parent." Record all 20 clips live — comfort, praise, bedtime, greeting. Load into the clip system. Test playback.
Hr 5–8 · Full loop test
Run the entire demo script end-to-end. Child asks a question → toy replies in storytelling mode. Cry audio plays → parent gets push notification. Fix whatever breaks.
→
Hr 8 checkpoint: every feature works end-to-end. If something is broken beyond 30 min of fixing, cut it from the demo. A clean 3-feature demo beats a buggy 4-feature one.
Hr 8 – 14
Build live
Phase 2
Connect parent app to live data + build surprise feature
BUILT LIVE AT HACKATHON
Hr 8–10 · Live data pipeline
Connect React parent app to Firebase. Real cry events and mood logs should appear on the dashboard as the toy runs. Judges watch data appear in real time.
Hr 10–12 · Daily report card
Build the AI-generated daily summary: call Groq with today's event log → get one paragraph like "Priya seemed excited today, asked about space 4 times, was comforted once at 2pm."
Hr 12–14 · Surprise feature
Milo's memory. Toy remembers the last 3 things the child talked about. Next conversation starts with "Hey! Last time you asked about dinosaurs — want to hear something cool?" 2 hours, huge impact.
→
Why this is the "built live" phase: the daily report card and memory feature are new code written at the hackathon. Judges can see git commits. This is your proof you built something on the day.
Hr 14 – 20
Polish
Phase 3
Polish, stress test, build pitch deck and demo script
DEMO PREP
Hr 14–16 · Break it on purpose
Ask the toy unexpected questions. Try edge cases. Yell at it. Cry loudly. Ask two questions at once. Find every failure mode before judges do. Fix the critical ones only.
Hr 16–18 · Pitch deck
5 slides max: problem → Milo solution → 4 features → live demo → future roadmap (Model 1, 2, 3). One person writes this while others are testing. Do not spend more than 2 hours on slides.
Hr 18–19 · Demo script
Write the exact 90-second demo flow. Every word. Who speaks. When the toy is touched. When the phone is shown. When the cry is triggered. Rehearse it twice out loud as a team.
Hr 19–20 · Code freeze
No new code after hour 20. Commit everything. Tag the release. Back up to a USB drive. From this point, you are only rehearsing and resting — never coding.
→
Code freeze at hour 20 is non-negotiable. Every team that loses a hackathon was still coding at hour 23. The last 4 hours are for sleep and rehearsal, not features.
Hr 20 – 22
Sleep
Phase 4
Sleep in shifts — one person monitors the system
REST
Person A + B sleep
2 hours of actual sleep. Set an alarm. You will present 10× better rested than exhausted. This is not optional — it is strategy.
Person C monitors
Keep the toy running. Make sure Firebase is live. Make sure no process has crashed. Do not write new code. Just watch and keep it alive.
Hr 22 – 24
Present
Phase 5
Final rehearsal and presentation
WIN
Hr 22 · Wake + rehearse
Everyone awake. Run the full demo script one more time. Confirm toy is working. Confirm phone notifications fire. Confirm parent app opens on judge's phone via QR code.
Hr 23–24 · Present
Toy on table. Teammate plays the child. One person speaks. One person manages the phone. Let the toy do the talking — your job is to narrate what judges are feeling.
→
The presentation is not a feature walkthrough. It is a story about a child who misses their parent — and how Milo solved that. Every judge has a child, or was one. Start there.
What the pre-work actually buys you
8hrs
Saved on debugging infrastructure
Teams without pre-work spend the first 8 hours fighting dependencies, broken APIs, and audio drivers. You spend it integrating a working system. You're already ahead by lunchtime.
2hrs
Spent building something brand new
The memory feature and the AI daily report card are genuinely new code written at the hackathon. They show up in your git log. Judges who check commits see real hackathon-day work.
4hrs
For pitch, script, and sleep
Most teams skip this entirely. A team that sleeps, rehearses a tight demo, and walks in with a clear story beats a team with more features and zero presentation polish every single time.
0
Risk of core demo breaking
The four core features are battle-tested from 15 days of prep. The only new code at the hackathon is additive — if it breaks, you cut it. The core never wobbles.
1
Surprise that makes judges remember you
"Milo remembers." When the toy opens with "Hey, last time you asked me about dinosaurs..." — that's a feature no judge will forget. It takes 2 hours and only exists because you had time to build it.
∞
Confidence walking into the room
You know exactly what Milo does, how it fails, and how to recover. You've rehearsed the demo. You've slept. That confidence is visible to judges — and it is itself a signal of a strong team.
The demo moment that wins the room
The 90-second Milo demo script
Rehearse this exact sequence. Every word matters. Every pause is intentional.
01
Set the scene (15 seconds)
Presenter says: "It's 3pm. Both parents are at work. Their 5-year-old is home with a caretaker. This is Milo." Place the toy on the table. Say nothing else. Let the silence build.
02
The child asks (20 seconds)
Teammate leans toward toy: "Milo, why is the sky blue?" Milo responds — funny, curious, story-driven. Something like "Great question! Imagine the sky is a giant bowl of cereal and sunlight is the spoon..." Judges smile.
03
The memory moment (15 seconds)
Teammate walks away, comes back: "Milo, hi!" Milo says: "Hey! Last time we talked you asked me about the sky — want to hear something even cooler about space?" The room goes quiet. That's the moment.
04
The parent voice moment (20 seconds)
Trigger the cry audio near the mic. Milo immediately plays the parent's recorded voice: "Hey baby, mama's here, it's okay." Simultaneously, show the judge's phone — push notification just arrived. Two things happening at once. Pure product.
05
The parent app close (20 seconds)
Show the phone. "This is what the parent sees at the end of the day." Daily report card: topics, mood arc, cry log. Presenter closes with: "Milo isn't a toy. It's a presence. The first product that makes a child feel their parent is always there."
